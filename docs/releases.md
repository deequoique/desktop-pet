# 发布与打包

正式发布由 `v*` tag 触发 GitHub Actions。流程构建 Windows NSIS、macOS x64/arm64 包，以及带生产依赖的 Linux server 压缩包。`PET_SERVER_URL` 从 GitHub Secret 生成客户端生产配置，房间密钥、ElevenLabs Key 和 DashScope Key 不进入安装包。

## v1.6.1

这是 1.6 系列的正式稳定更新，合并了 `v1.6.1-beta.1` 至 `v1.6.1-beta.4` 在真实网络中验证的诊断、画质与部署改进，并补齐 Windows 桌宠窗口修复。服务器与双方所有客户端应同步升级。

- 设置页新增用户主动触发的完整诊断导出，覆盖应用崩溃、Socket、媒体权限、ICE、selected pair、RTP 和稳定错误码；应用不会后台上传诊断数据。
- P2P 屏幕共享按网络状态在 `480p30` 至 `2K90` 的有限档位内自适应，修复 Chromium 初始带宽估算导致画质长期锁死在低帧率的问题。
- TURN 屏幕共享采用独立的 `480p30 → 720p30 → 720p45` 有界策略；轻度拥塞逐档回退，严重延迟、丢包或抖动立即回到保守档位。
- 摄像头使用独立 selected pair 决策：P2P 可手动开启，TURN 会停止发送与采集并释放硬件；未开启或被 TURN 禁用时不再显示空白摄像头窗口。
- 服务端诊断增加按 `callId` 对齐的结构化日志与 PM2 轮转配置；Linux 发布包补齐持久化目录、PM2 配置和诊断部署脚本，更新服务端不再误删用户数据。
- Windows 发布工作流为 pet 与 web 依赖使用隔离 npm cache，避免安装阶段互相清理；正式包继续生成 Windows、macOS 和 Linux server 资产。
- 修复 Windows 125% DPI 下点击或拖动桌宠时窗口尺寸逐帧变大的问题；静止点击不再触发原生窗口更新，拖动期间保持实际宽高不变。

从 `v1.6.0` 或更早版本升级时，必须同时升级服务器与双方所有客户端。

## v1.6.1-beta.4

这是用于真实 TURN 带宽和摄像头独立选路复测的测试版。服务器协议增加了摄像头 `relay_disabled` 状态，服务器与参与测试的双方客户端应同时升级。

- TURN 屏幕共享由固定 360p5 改为 `480p30 → 720p30 → 720p45` 有限自适应，最高码率固定为 1.875 Mbps，不进入 1080p。
- TURN 在轻度拥塞连续出现时逐档回退，严重延迟、丢包或抖动立即回到 480p30；P2P 七档最高 2K90 的策略保持独立。
- 摄像头使用自己的 selected pair 决策：P2P 可以手动开启，TURN 会自动断开发送、停止采集并释放硬件；恢复 P2P 后不会未经用户操作自动重开。
- 摄像头 ICE 延迟到主通话连通并完成选路后再预热，避免接通阶段两套 ICE 同时竞速。
- 对方摄像头未开启、关闭或因 TURN 禁用时不再显示空白摄像头窗口，屏幕自动使用主画面。

## v1.6.1-beta.3

这是用于复测 P2P 长时间卡顿和 5fps 自锁的测试版。服务器协议没有变化，参与测试的双方客户端应同时升级。

- 修复健康 IPv4/IPv6 P2P 因 Chromium 初始 `availableOutgoingBitrate` 偏低而被永久锁在 1 档、5fps 的问题；该估算现在只作为延长升档观察的软信号。
- P2P 屏幕共享改为独立调整清晰度与帧率，内部按 `480p30 → 720p30 → 720p45 → 1080p45 → 1080p60 → 2K60 → 2K90` 逐级试探。
- P2P 编码器优先维持帧率；普通拥塞沿状态表逐级回退，严重 RTT、丢包或抖动可立即回到 480p30。
- TURN 继续固定为 640×360、5fps、240 kbit/s，不增加中继服务器流量。
- 诊断包新增帧率目标、网络健康目标、带宽估算档位和状态变化原因，便于区分真实拥塞与恢复试探。

## v1.6.1-beta.2

这是用于真实 IPv4/TURN 网络复测的自适应画质 Beta，服务器和参与测试的双方客户端需要同时升级。

- 通话侧栏实时显示网络等级、有效路径、RTT、接收码率、帧率和当前视频档位。
- 屏幕共享和双方摄像头改为五档画质，根据 RTT、带宽、丢包、抖动和 RTP 状态快速降档、稳定后逐档恢复；TURN 始终锁定最低档以优先保证声音与画面连续。
- 修复 coturn 私网 allocation 经公网 NAT 后显示为 `prflx` 而被误判为 P2P 的问题；TURN host、`relayProtocol` 和 relay alias 现在使用统一判定。
- 周期诊断改为有界的 selected-pair/RTP 摘要，常见的 ICE 600/701 网卡探测失败不再制造 incident 写入风暴。
- coturn 部署验证新增 `external-ip`、`relay-ip` 与 relay 端口范围检查；公网/私网双地址服务器必须配置精确映射。

## v1.6.1-beta.1

这是用于真实网络故障复盘的诊断 Beta，服务器和参与测试的双方客户端需要同时升级。

- 设置页新增“诊断与故障”，由用户主动导出单个 JSON 诊断包；应用不会后台上传。
- 自动记录 renderer/main 异常、崩溃 metadata、异常退出、Socket、媒体权限和稳定错误码，并在用户下次打开控制面板时显示持久 fatal 提示。
- WebRTC 记录 ICE gathering、候选生成/排队/添加结果、STUN 错误和 selected candidate pair；保留 IPv4/IPv6 地址、端口、协议与 RTT 以定位直连失败。
- 服务端输出可按 `callId` 对齐的结构化 JSON，并在通话结束时汇总主通话/摄像头的 offer、answer、candidate 类型和转发结果。
- 新增 PM2 20 MB × 7 份压缩轮转配置和服务器诊断操作说明；诊断中不会包含密钥、完整 SDP、原始 candidate、便签/TTS 正文或媒体内容。

## v1.6.0

这是一次需要服务器和双方客户端同步升级的异步桌面便签版本。

- 新增可投递到对方桌面的便签，支持文本、JPEG/PNG 图片和网页链接；歌曲与视频通过链接分享，不上传视频文件。
- 多张便签可以同时置顶展开，也可以从桌宠下方的邮箱进入便签堆；新便签通过角标与桌宠状态提醒，不播放提示音。
- 邮箱按钮支持再次点击关闭便签堆；便签堆新打开时会按内容自适应高度，并保留自由缩放能力。
- 新增明确的“已批阅”流程，并支持用文字、Emoji 或图片批阅并回复；已投递便签不提供撤回和编辑。
- 便签可收藏并跨设备同步；图片与收藏均有服务端容量约束，避免无界占用存储空间。
- 游戏模式会临时隐藏已展开的便签，退出游戏模式后只恢复此前可见的窗口。

从 `v1.5.0` 或更早版本升级时，必须同时升级服务器与双方所有客户端。

## v1.5.0

这是一次需要服务器和双方客户端同步升级的通话功能版本。

- 新增单向摄像头视频：发送方可以预览自己的摄像头状态，双方控制面板都可以开关摄像头；关闭后会停止媒体 track 并真正释放摄像头硬件。
- 新增系统级媒体浮窗：只显示屏幕共享和摄像头画面，可置顶、移动和自由调整宽高；视频以完整不裁切的方式适配窗口。
- 屏幕共享控制权集中到控制端：控制端可以停止或恢复远端屏幕共享，桌宠端不提供停止入口，退出软件仍会结束共享并释放资源。
- 屏幕与摄像头支持主次画面切换、隐藏和自动顶替；关闭浮窗会把媒体视图送回控制面板，不会结束通话。
- 控制面板通话按钮采用更紧凑且一致的尺寸，减少对主要媒体画面的遮挡。
- 增强苏州等复杂网络环境下的连接诊断和安全降级：选路未知时不发送视频；TURN relay 使用固定低清屏幕/摄像头上限并优先保留音频。

从 `v1.4.1` 或更早版本升级时，必须同时升级服务器与双方所有客户端。

## v1.4.1

这是 1.4 系列的首个正式版本，包含 Beta 阶段验证过的双成员多设备、个人音频库、新控制面板、通话、桌宠缩放和诊断能力，并补充以下体验改进：

- 控制面板每次启动默认打开设置；首次配置先验证服务器与密钥，再选择真实成员身份。
- 已连接用户可以更改当前身份；设备记录随身份迁移，个人音频仍归原成员。
- 快捷互动只显示桌宠真实支持的“开心、跳跃、委屈、等待”，动作文字与动画一致。
- 快捷互动按钮增加按压反馈，不再把第一个按钮永久显示为黑色选中态。
- 正式版显式允许检查后续 prerelease，便于愿意尝鲜的安装继续接收 Beta。

从 `v1.4.0-beta.1` 或更早版本升级时，必须同时升级服务器与双方所有客户端。

## 未签名 macOS 应用

当前 macOS 包未接入 Apple Developer 签名和 notarization。下载 DMG、把 `Desktop Pet.app` 拖入“应用程序”后，如果系统提示“无法验证开发者”或“应用已损坏”，可以在 Terminal 中完整执行：

```bash
APP="/Applications/Desktop Pet.app"

if [ ! -d "$APP" ]; then
  echo "没有找到 $APP；请先把 Desktop Pet.app 拖入应用程序文件夹。" >&2
  exit 1
fi

xattr -dr com.apple.quarantine "$APP" || exit 1
open "$APP"
```

这段命令只移除该应用自身的下载隔离属性，不会关闭系统 Gatekeeper。只对从本项目 GitHub Release 下载且确认来源可信的包执行；不要使用 `spctl --master-disable` 等全局关闭安全检查的命令。

也可以不使用 Terminal：在 Finder 中按住 Control 点击应用并选择“打开”，或首次拦截后前往“系统设置 → 隐私与安全性”选择“仍要打开”。Apple 签名和 notarization 暂不在当前路线内。

## 自动更新

Electron 使用 GitHub Releases 检查更新。私有 Release 不应把 GitHub token 打进客户端；更适合公开发布资产或后续迁移到自有 generic 更新源。
