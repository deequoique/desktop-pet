# 修复 Windows 点击桌宠尺寸漂移

## 目标

修复 Windows 分数 DPI（诊断机为 125%）下点击或拖动桌宠时窗口尺寸逐帧变大的问题，同时保持现有拖拽、缩放和位置持久化行为。

## 已确认事实

- 故障诊断中，恢复默认后窗口实际为 `181×241`、保存 scale 为 `1.006`；一次点击期间窗口在约 279ms 内从 `183×243` 连续增长到 `200×261`。
- 尺寸增长期间没有 `pet-scale-applied` 事件，因此不是 +/-、控制面板或 reset 缩放请求造成的。
- `pet/src/main/index.js` 的拖拽轮询每 16ms 调用一次 `BrowserWindow.setPosition()`，即使光标和目标窗口位置没有变化。
- Windows 125% DPI 下，重复只设置位置会在 DIP 与物理像素转换中累积窗口尺寸取整漂移；现有 resize 日志与该 16ms 调用完全同频。

## 需求

- R1：单击并按住桌宠但不移动光标时，不得重复调用会改变原生窗口 bounds 的 API。
- R2：拖拽开始时以主进程读取到的实际窗口 bounds 为尺寸基准；整个拖拽期间只能改变 `x/y`，不得累积改变 `width/height`。
- R3：保持现有绝对光标驱动拖拽、游戏模式穿透、renderer 光标流、缩放入口和持久化契约不变。
- R4：不得引入固定 DPI 比例补偿；修复应直接消除无效窗口调用和尺寸反馈漂移。
- R5：增加自动化回归测试，约束拖拽移动使用冻结尺寸并跳过无位置变化的更新。

## 验收标准

- [x] AC1：按下桌宠且光标不动时，轮询不会调用 `setPosition()` 或 `setBounds()`。
- [x] AC2：光标移动时，主进程原子应用目标 `x/y` 与拖拽开始时冻结的实际 `width/height`。
- [x] AC3：拖拽结束、进入游戏模式或应用退出时，拖拽尺寸快照会被清理。
- [x] AC4：pet 自动化测试通过，并包含 Windows 分数 DPI 尺寸漂移的源码级回归断言。
- [x] AC5：`npm run build:pet` 通过。

## 范围外

- 修改 Electron 版本或加入平台专用 DPI 比例换算。
- 修改桌宠尺寸上下限、缩放 UI 或保存 scale 的语义。
- 本次诊断文本中 WebRTC/ICE 地址的额外脱敏；作为独立隐私加固处理。
