# 桌面便签功能

## Goal

让用户把关心、提醒或分享以非即时的便签投递到对方桌面，形成“投递 → 待处理 → 显式批阅”的闭环，并与需要即时往返的聊天保持清晰区别。

## Background

- 房间固定两名成员，每名成员可以有多台设备；便签投递给对方成员，而不是指定设备。
- 便签是持久、异步对象：接收方可以离线，未批阅内容不自动过期。
- 展开的便签是始终置顶的桌面卡片；桌宠扮演“送信员”，信封入口统一承载新件提示和便签堆。
- “新便签”只表示接收方尚未主动交互；“未批阅”表示尚未显式处理。发送方只能看到批阅结果，看不到被动已读状态。

## Requirements

### 1. 投递、身份与状态同步

- 发送成功以服务器完成持久保存为准；接收方是否在线不影响投递，保存失败不得伪装成已发送。
- 便签属于接收成员，并同步到该成员所有设备。正常模式下所有在线设备直接展开新便签；离线设备下次上线后同步。
- 任意接收设备首次主动交互后，成员级“新便签”状态在其所有设备清除，但不向发送方回传“已查看”。自动展开本身不算主动交互；点击、拖动或打开媒体算主动交互。
- 任意设备完成批阅后，成员级批阅状态同步到其他设备。
- 桌面坐标、尺寸、是否收进便签堆等布局状态仅保存在当前设备，不跨设备同步。
- 便签发送后不可编辑或撤回；内容有误时只能另发新便签。

### 2. 内容模型与输入限制

- 单张便签允许纯文本，或“可选正文 + 最多一个媒体内容”。媒体内容只能是图片、歌曲链接或视频链接之一；空便签不得发送。
- 正文最多 1,000 个 Unicode 用户可见字符；批阅回复最多 500 个。客户端实时显示剩余字数，服务端独立执行相同语义校验，不按 UTF-8 字节或 UTF-16 代码单元误算组合 emoji。
- 单张服务端图片默认上限 2 MB；客户端上传前压缩，服务端独立校验。视频或音频文件不得上传。
- 歌曲与视频仅保存 URL 和少量预览元数据，不下载、代理或缓存音视频。卡片显示标题、来源和可用的封面/缩略图；解析失败时退化为域名与原始链接。点击后交由系统浏览器或对应应用打开，便签内不播放媒体。
- 发送方从五种预设纸色中选择：奶油黄 `#F4D77D`、温柔粉 `#E8B7C8`、雾蓝 `#AFC9D8`、鼠尾草绿 `#B8C9A3`、淡紫灰 `#C8B7D8`。不提供任意取色、字体或复杂皮肤；系统自动保证前景对比度。
- 接收方可在本机启用高对比度显示覆盖纸色，但不修改保存的原始颜色。

### 3. 桌面展示、便签堆与桌宠提醒

- 正常模式下新便签直接展开、显示“新便签”角标且不抢键盘焦点；展开数量不设 UI 硬上限。
- 所有展开便签始终置顶，不提供逐张取消置顶。卡片可调整大小，但必须设置保证内容与操作可用的最小尺寸。
- 新卡片出现在桌宠当前显示器附近，不遮挡桌宠或信封入口；连续新件以约 24px 阶梯偏移，触及工作区边缘时换向并保持完整可见。移动桌宠不带动既有卡片，只影响后续新卡片位置。
- 每张卡片提供“收进便签堆”，不生成独立最小化图标。收堆、重新展开、移动和缩放不等于批阅；主动执行这些交互仍按规则清除“新便签”状态。
- 未批阅便签不能直接删除，只能收进便签堆，或通过“仅批阅 / 批阅并回复”结束待处理状态。
- 桌宠下方的信封入口同时显示新便签数和未批阅总数，可打开轻量便签堆、单张展开、全部展开或跳转“写一张便签”。新件到达时桌宠短暂进入收信状态；“新便签”清除后停止新件动作，未批阅数量继续显示。
- 便签到达、批阅和收藏均不播放提示音。
- 现有游戏模式是唯一勿扰模式：期间新便签只入堆、不展开、不发声，桌宠继续鼠标穿透。退出游戏模式后只恢复新件状态与角标，不批量弹出；系统不自动侦测其他全屏应用。

### 4. 批阅与批阅回复

- 批阅必须由接收方显式执行，展示或打开不能自动批阅。批阅后卡片退出桌面待处理区域，并进入历史记录。
- 接收方可选择“仅批阅”或“批阅并回复”。发送方可看到批阅状态、批阅时间和回复。
- 批阅回复归属于原便签的终态回执，不创建聊天线程，也不允许继续回复。
- 回复可包含短文本（包括 Unicode emoji）和最多一张图片，二者至少存在一种；提供常用 emoji 快捷选择，不支持自定义表情包、多图、GIF 或视频。
- 回复图片沿用客户端压缩、服务端 2 MB 单图上限和收藏图片配额。
- 批阅与回复必须原子提交：回复保存成功后才进入已批阅；失败时保持未批阅并允许重试。

### 5. 历史、收藏与清理

- 发送方和接收方都能独立收藏各自可见的便签；收藏是成员私有状态，不通知对方，也不改变对方收藏。
- 收藏跨同一成员所有设备同步。发送方收藏在对方批阅后可同步包含批阅回执的完整版本。
- 收藏保留便签快照并引用原服务端附件，不复制相同媒体文件；客户端可缓存，但服务器仍是跨设备同步权威。
- 默认每位成员最多收藏 500 张便签，收藏引用的图片合计最多 500 MB；达到任一上限时明确拒绝新增收藏，不自动淘汰旧收藏。数量、空间和单图上限均允许服务器配置。
- 未被任何一方收藏的已批阅便签在服务器保留 30 天，随后删除便签、回复及无其他引用的附件。
- 任意一方收藏时，该方快照与关联图片不受 30 天历史期限影响；双方取消收藏且普通历史已到期后，服务器才可清理最后一个附件引用。

### 6. 容量保护

- 默认每位接收成员最多积累 500 张未批阅便签，未批阅便签引用图片合计最多 500 MB；两项均允许服务器配置。
- 达到任一未批阅配额时，服务器以稳定错误码拒绝新投递，发送方看到“对方便签箱已满”。失败投递不进入成功发件记录，且不得覆盖或删除既有内容。
- 默认每个双人房间的便签图片总占用最多 2 GB，统计未批阅、30 天历史和收藏引用的所有唯一图片；同一附件被多个状态引用时不得重复计数。
- 房间图片总量达到上限后，只拒绝新的图片便签和图片批阅回复；纯文本、歌曲链接、视频链接、无图批阅和无图回复继续可用。
- 图片回复因房间总量不足而失败时，便签保持未批阅，接收方可以移除图片后改用文字回复或仅批阅。
- 房间图片总上限允许服务器配置；达到上限不得自动删除既有图片、历史或收藏。

### 7. 界面归属

- 控制面板新增完整“便签”页面，负责编辑发送、发件记录、批阅回执和跨设备收藏管理。
- 桌面便签卡片负责接收、查看、缩放、收堆、收藏和批阅；卡片只提供收藏快捷操作，不承载完整历史管理。
- 桌宠信封只打开轻量便签堆；“写一张便签”打开控制面板的便签编辑页。

## Acceptance Criteria

### Delivery and synchronization

- [ ] 对方离线时，服务器保存成功后发送方看到投递成功；保存失败时看到明确失败，且发件记录不出现伪成功。
- [ ] 发送方无需选择设备；正常模式下对方所有在线设备收到并展开便签，离线设备下次上线同步。
- [ ] 自动展开不清除“新便签”；任意设备首次点击、拖动或打开媒体后，同成员其他设备同步清除角标，但发送方看不到已查看回执。
- [ ] 任意设备批阅后，同成员其他设备同步退出未批阅状态；布局变化不跨设备同步。
- [ ] 已发送便签没有编辑或撤回入口，内容不会被静默替换。

### Content and validation

- [ ] 纯文本以及“可选文字 + 单张图片/单个歌曲链接/单个视频链接”均可发送；空便签、多媒体、多图或混合多种媒体被拒绝。
- [ ] 正文 1,000、回复 500 个用户可见字符处仍可提交，再多一个即被客户端阻止并被服务端拒绝；组合 emoji 不被重复计数。
- [ ] 超过默认 2 MB 或服务端配置上限的图片被拒绝；视频/音频文件不存在上传入口且服务端拒绝对应 payload。
- [ ] 歌曲/视频显示外部预览卡片并可打开；预览解析失败时仍能显示和打开原始链接，外部播放不会改变批阅状态。
- [ ] 五种预设纸色在所有设备一致且控件可读；本机高对比度覆盖不回写原便签。

### Desktop experience

- [ ] 正常模式新便签在桌宠所在显示器附近阶梯展开、完整位于工作区、不遮挡桌宠/信封且不抢键盘焦点。
- [ ] 所有展开卡片始终置顶，可调整到不小于可用最小尺寸，且展开数量没有 UI 硬上限。
- [ ] 用户可收进统一便签堆并单张或全部展开；桌面不产生独立最小化图标。
- [ ] 未批阅便签没有直接删除入口；收堆、移动和缩放均不会批阅。
- [ ] 信封入口正确显示新件数与未批阅数，并可打开便签堆和跳转写便签；桌宠新件状态在首次主动交互后停止。
- [ ] 游戏模式期间新件只入堆、不展开、不发声；退出后不批量弹出。正常模式同样不播放任何便签提示音。

### Review, history, and favorites

- [ ] 打开便签不会自动批阅；“仅批阅”成功后卡片退出待处理区，发送方看到批阅时间。
- [ ] “批阅并回复”接受文本/emoji、单张图片或组合；空回复、多图、GIF、视频或超限图片被拒绝。
- [ ] 回复保存失败时仍未批阅；成功后发送方在原记录看到终态回复且没有继续回复入口。
- [ ] 双方可独立收藏；一台设备的收藏变化同步到同成员其他设备，不通知或改变对方收藏。
- [ ] 收藏不会复制服务端图片，且收藏内容不会因普通历史到期而失效。
- [ ] 默认第 501 张收藏、收藏图片超过 500 MB、第 501 张未批阅便签或未批阅图片超过 500 MB 时，相应操作明确失败，既有内容保持不变；管理员可调整全部配额。
- [ ] 房间唯一便签图片达到默认 2 GB 后，新增图片便签和图片回复明确失败，而文本/链接便签及无图批阅继续成功；管理员可调整总上限。
- [ ] 房间满额不会触发自动清理；同一图片被历史与收藏共同引用时只计一次空间。
- [ ] 未收藏的已批阅便签在 30 天后清理；存在收藏引用时关联快照与附件继续可用，最后引用消失且历史到期后才清理。

### Interface boundary

- [ ] 控制面板可以编辑发送、查看发件记录/批阅回执/收藏；桌面卡片可以收堆、收藏和批阅；桌宠信封可以打开便签堆并跳转编辑页。
- [ ] 便签不会作为普通即时聊天消息展示、排序或处理。

## Out of Scope

- 视频或音频文件上传，以及服务器代理、下载或缓存外部音视频。
- 便签内嵌歌曲或视频播放器。
- 单张便签的多媒体、多图或多链接附件。
- 批阅回复中的多图、GIF、视频、自定义表情包或连续对话。
- 任意纸色、字体和复杂皮肤编辑。
- 已发送便签的编辑或撤回。
- 未批阅便签的直接删除或自动过期。
- 按任意全屏应用自动切换勿扰状态。
- 为每张收起便签创建独立桌面最小化图标。
