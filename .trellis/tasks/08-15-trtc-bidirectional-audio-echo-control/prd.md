# 实现 TRTC 双向独立音频与回声消除

## Goal

在保留现有 TRTC 游戏屏幕与系统声音单向共享能力的前提下，把麦克风从当前单向模式升级为可靠的双向通话：屏幕共享方继续单向发布屏幕和系统声音，双方都能发送自己的麦克风；接收方可以分别决定是否收听共享方的系统声音和麦克风，屏幕共享方也能独立控制是否收听对方麦克风；同时在 Windows 11 上消除远端播放再次被本地采集、发送所造成的回声和循环反馈。

## Background and Confirmed Facts

- TRTC 主媒体已接入 Electron 内置控制窗口，当前 server 为通话双方各签发一个 call-scoped TRTC 用户身份（`server/src/index.js:49-74`）。
- server 只让被呼叫的目标设备发布屏幕与系统声音，发起设备只订阅，因此当前主媒体方向由 `publishScreen: participantId === call.targetDeviceId` 固定为单向（`server/src/index.js:72`）。
- 发布端启动屏幕共享时会在同一个 TRTC 用户身份上同时启动本地音频和系统音频回环；麦克风只通过 capture volume 在 0/100 之间切换（`pet/src/main/trtc-preload-bridge.js:181-185`、`pet/src/main/trtc-preload-bridge.js:220-231`）。
- 接收端目前只能调用用户级 `muteRemoteAudio(userId, muted)`；该调用会同时影响该用户的麦克风与系统声音（`pet/src/main/trtc-preload-bridge.js:236-244`）。
- React 控制面板因此在 TRTC 模式下只显示一个“对方声音”开关，并在操作后把麦克风和系统声音的静音状态一起修改（`web/src/App.tsx:1924-1941`、`web/src/App.tsx:2688-2693`）。
- 当前实现会在同一 TRTC 实例既接收远端声音又启动系统音频回环；如果远端播放被系统回环或扬声器麦克风再次采集，就会形成一次或多次回传路径。任务必须以音频路由和可验证的 AEC/防回采策略解决根因，不能仅靠降低音量掩盖。
- 2026-08-15 用户确认屏幕画面继续由当前屏幕共享方单向发布，系统声音仍与该角色绑定并保持单向；只有麦克风升级为双方都可发布的双向媒体。
- 2026-08-15 用户澄清：双向麦克风、单向系统声音和独立收听控制不能限定为 Windows-only，必须继续覆盖现有 Windows 与 macOS TRTC 客户端；只有回声消除允许首版不支持 macOS。Linux 当前只作为 server 发布资产，不属于本任务的 TRTC Electron 客户端范围（`.trellis/spec/desktop-pet/shared/webrtc-networking-and-deployment.md:418-472`）。
- 2026-08-15 用户确认采用安全默认：进入每次通话时双方自己的麦克风、远端麦克风播放和远端系统声音播放全部关闭，用户在本机逐项打开。
- 2026-08-15 用户拒绝按游戏/目标应用选择 exe 的系统声音采集，因为每次手动选择会破坏现有无感共享体验；Windows 必须继续采集整机声音，但从回环采集中排除本 Electron/TRTC 进程树的播放，切断远端人声的数字回传路径。
- 2026-08-15 用户将产品范围简化为 Windows 11 回声消除：Windows 11 启用 Electron/TRTC 进程树排除；Windows 10 继续使用现有未排除的整机系统回环，即使可能产生数字回声。Windows 10 不得因为缺少排除接口而关闭系统声音共享。
- 相关前置任务为 `.trellis/tasks/08-12-evaluate-trtc-game-sharing/`；新任务继承其 UserSig、房间映射、Electron preload 安全桥接、30fps 屏幕共享、feature flag 和 WebRTC 回滚约束，不重复迁移主媒体基础设施。

## Requirements

### R1. 双向实时语音

- 通话建立后，双方都可以独立打开或关闭自己的麦克风；任一方是否共享屏幕不得限制另一方发送麦克风。
- 双方同时打开麦克风时必须支持自然的全双工交谈，不能因一方说话而静音或压制另一方。
- 每次进入通话时双方自己的麦克风默认关闭，不继承上次通话的开启状态；权限拒绝、设备丢失和重新打开行为必须在两端一致，单个音频源失败不能结束屏幕共享或整个通话。

### R2. 远端系统声音与麦克风独立收听

- 非屏幕共享方拥有“对方系统声音”和“对方麦克风”两个独立开关；切换其中一个不得改变另一个的状态、音量、订阅或发布状态。
- 屏幕共享方只接收对方麦克风，并拥有独立的“对方麦克风”收听开关；不得显示或订阅并不存在的对方系统声音。
- 每次进入通话时，所有远端麦克风和远端系统声音的本地播放默认关闭，不继承上次通话的收听状态；用户必须逐项明确打开。
- 独立控制必须建立在可区分的远端音频源或等价的独立路由上，不能只在 UI 中维护两个状态却仍对同一混合流整体静音。
- 本地的收听选择只影响本机播放，不得远程关闭对方采集；双方各自拥有自己的麦克风发布权，系统声音发布继续由屏幕共享方承担。

### R3. Windows 11 回声与反馈消除

- Windows 11 上，TRTC 远端播放不得被本机系统声音回环重新发布给对方。
- Windows 11 屏幕共享方必须保持无需选择应用的整机声音采集，同时从系统回环中排除本 Electron/TRTC 进程树；不得要求用户选择游戏、目标 exe 或逐个维护应用白名单。
- Windows 11 排除本应用后，独立启动的游戏、播放器等其他进程声音仍须正常进入单向系统声音上行；本应用/TRTC 播放的远端麦克风和其他远端媒体不得进入该上行。
- Windows 扬声器播放被本机麦克风拾取时，应使用 TRTC/系统提供的回声消除链路；不得为音乐质量模式或自定义路由无意关闭 AEC。
- Windows 11↔Windows 11 同时开启麦克风和扬声器、共享方同时发布系统声音时，不得出现逐轮增强的循环反馈、重复人声或持续回声。
- Windows 10 继续调用 TRTC 现有整机 system loopback，不启用 native 排除；UI/诊断需标明当前系统不支持回环排除，但继续发布系统声音，数字回声不作为该配置的失败条件。
- Windows 上必须明确系统音频采集/播放排除能力和 TRTC AEC 支持边界；耳机提示不能替代 Windows 11 正常扬声器环境中的回声治理。macOS 首版不承担免提回声消除验收，但核心双向音频和独立收听功能仍必须可用。

### R4. 音频源生命周期与状态

- 麦克风、系统声音、远端麦克风订阅和远端系统声音订阅必须分别建模，状态在 call ID、断线重连和窗口生命周期内保持一致。
- 挂断、退出房间、窗口关闭、设备断开和初始化失败时，必须停止相应 capture/loopback/playout，移除 listener，并释放 TRTC/native 资源。
- 跨异步边界必须按当前 call 和实例代次丢弃迟到结果，旧通话不得复活音频采集或修改新通话状态。
- 音频开关和可用性状态需要通过现有诊断体系记录，但不得记录原始音频或敏感设备信息。

### R5. 兼容、灰度与成本

- 双向麦克风、单向系统声音和独立远端音源控制必须兼容 Windows 与 macOS TRTC Electron 客户端；不得因 Windows 回声消除实现让 macOS 无法进房、发布或控制音频。
- 保留现有 `TRTC_MEDIA_MODE` 回滚路径；本任务不得删除当前 WebRTC/coturn 主媒体实现。
- 保留 Electron `contextIsolation: true`、`nodeIntegration: false`，所有 native TRTC 能力继续通过窄 preload bridge 暴露。
- 设计需要说明为分离系统声音与麦克风而增加 TRTC 身份、房间成员或自定义音频链路时的安全、计费和并发影响。
- 不得改变当前屏幕及系统声音的单向发布角色，也不得破坏现有 720p30/1080p30 屏幕辅流、按需摄像头 WebRTC、UserSig 保密和 call-scoped 房间身份约束。

## Acceptance Criteria

- [ ] A、B 任一端都能独立打开/关闭自己的麦克风；双方同时开启时能够持续双向交谈，屏幕共享保持正常。
- [ ] 新通话建立后，两端自己的麦克风、远端麦克风播放和远端系统声音播放均为关闭；结束后重新通话仍恢复该默认值，不沿用上次选择。
- [ ] 非屏幕共享端显示并实际执行“对方系统声音”和“对方麦克风”两个独立收听开关；四种组合（都开、仅系统声、仅麦克风、都关）均与实际播放一致。
- [ ] 屏幕共享端只收到并控制对方麦克风，不收到对方系统声音；双方的麦克风开关和收听状态互不影响。
- [ ] 自动化测试证明 TRTC 模式下非共享端切换一个远端音频源不会修改或静音另一个源，且状态不是对单一混合流的伪分离。
- [ ] Windows 11↔Windows 11 双机扬声器测试中，双方同时开启麦克风并交替/同时说话至少 10 分钟，不出现持续回声、重复回传或增益逐轮放大的啸叫。
- [ ] Windows 11 双机系统声音测试中，本机播放的远端人声不会进入本机系统声音上行并再次返回对方；可用诊断或录音对照确认不存在二次回传路径。
- [ ] Windows 11 共享方无需选择游戏或 exe 即可发布整机声音；测试同时播放一个外部应用声音和 TRTC 远端人声时，对端只收到外部应用声音，不收到被回采的 TRTC 人声。
- [ ] 麦克风权限拒绝、系统声音采集失败、设备拔出和 TRTC 重连都只降级对应音频源，其他音频源、屏幕和通话保持可用。
- [ ] 挂断及窗口关闭后没有残留麦克风采集、系统 loopback、远端 playout、TRTC 音频发布/订阅或事件 listener；下一次通话按默认状态干净启动。
- [ ] Windows 11↔Windows 11 双机回声矩阵通过，覆盖双方扬声器、双方麦克风、共享方系统声音以及远端音频四种收听组合。
- [ ] Windows 10 会明确显示/记录“整机声音仍可共享，但当前系统不支持回环排除”，并实测继续通过旧 system loopback 发布系统声音；该配置出现数字回声不判失败。
- [ ] Windows↔macOS 完成功能矩阵：双方麦克风可双向发布、共享方系统声音保持单向、各角色的远端音频开关独立有效；macOS 上的免提回声消除不作为通过门槛。
- [ ] server/pet 自动化测试、web/pet 构建和 native TRTC 运行烟测通过；生成的 `web/src/*.js` 与 TypeScript 源保持同步。
- [ ] 设计文档量化所选音频分离方案的额外 TRTC 用量，并说明 feature flag 回滚步骤。

## Out of Scope

- 在本任务中把摄像头迁移到 TRTC。
- 双向或同时屏幕共享，以及非屏幕共享方发布系统声音。
- 要求用户手动选择游戏/目标应用、只采集单个 exe，或维护应用声音白名单。
- macOS 免提回声消除，以及 Linux TRTC Electron 客户端支持。
- 删除现有 WebRTC/coturn 回退实现。
- 云端录制、混流、CDN 旁路、语音转写、降噪增值服务或购买新的腾讯云套餐。
- 重做通话页面或屏幕共享交互；只增加完成音频控制所需的状态与控件。
